# Contributing to Intastellar Cookie Solutions

Thanks for your interest in contributing. This project supports transparency and open development, and contributions are welcome as long as they align with the project's goals: privacy-compliant consent handling, stability, performance and simplicity.

Please take a moment to read through this guide before submitting changes.

---

## 📌 Ways to Contribute

There are several ways to help improve the project:

- Report bugs
- Suggest improvements or new features
- Submit pull requests
- Improve or expand documentation
- Review existing issues and help others

---

## 🐞 Reporting Issues

Before opening a new issue, please:

1. Check the existing issue list to avoid duplicates.
2. Include:
   - Expected behavior
   - Actual behavior
   - Steps to reproduce
   - Browser/OS environment
   - Version of the script (if applicable)

Use the appropriate issue template if available.

---

## 🛠 Submitting a Pull Request

Pull requests are welcome, but please follow these rules:

1. **Fork** the repository and create a new branch:
2. Keep the changes focused and scoped to a single task.
3. Ensure the code is readable and consistent with the existing style.
4. Update documentation if your change affects API behavior.
5. Reference the related issue number in your PR description:

Pull requests that introduce large, unrequested features or rewrites may be rejected if they conflict with the roadmap.

---

## 🧪 Testing

Automated tests will be added as the project matures. For now, please:

- Test changes across major browsers (Chrome, Firefox, Safari, Edge).
- Ensure script blocking and consent logic behave as expected.
- Verify no errors appear in the console during normal usage.

---

## 📐 Coding Style

- Use clear variable names.
- Add comments only where logic isn’t obvious.
- Avoid unnecessary dependencies.
- Keep the code lightweight and performant.

This project prioritizes:
- Compliance accuracy
- Minimalism
- Browser performance

---

## 🎯 Roadmap Alignment

Before building a large feature, open an issue to discuss it first. This helps prevent effort spent on features that conflict with the direction of the project.

---

## 🔐 Security

If you discover a vulnerability, **do not open a public issue**.

Instead, email: security@intastellarsolutions.com
We’ll review and respond as soon as possible.
